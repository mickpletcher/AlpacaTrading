# 002 Living Documentation Standard Requirements

## Change Summary

Apply the Software Project Living Documentation Standard 2.2 to the existing repository in Adoption Mode.

## Requirements

1. Select the lowest defensible project tier and document the rationale.
2. Map exactly one authority to every responsibility before creating new authorities.
3. Preserve and adapt useful existing documentation.
4. Add only missing Tier 2 authorities.
5. Merge repository agent guidance into one root authority.
6. Add a machine-readable authority map and local documentation compliance check.
7. Base assessment and architecture claims on repository evidence.
8. Record active defects, debt, deferred upgrades, operations, validation limitations, and resolved history without duplication.
9. Run safe validation and record required waivers for unsafe or unavailable checks.
10. Do not change runtime trading behavior.

## Non-Goals

- Creating Tier 2C contractual documents.
- Fixing the defects found during assessment.
- Enabling live trading.
- Replacing component README files.
- Reconstructing requirements from existing code.
